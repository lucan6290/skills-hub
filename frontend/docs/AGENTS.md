# frontend/docs/ 文档维护规则

## 何时修改本目录文档

1. **代码结构变更**：新增/删除/移动源文件时，同步更新 `PROJECT_STRUCTURE.md`
2. **样式系统变更**：新增/修改/删除 CSS 变量时，同步更新 `THEME_STANDARD.md`
3. **组件模式变更**：新增/修改 Context、Hook、组件约定时，同步更新 `COMPONENT_STANDARD.md`
4. **API 模式变更**：新增/修改 API 调用方式、DTO 类型、错误处理时，同步更新 `API_STANDARD.md`
5. **发现代码与文档冲突时**：以当前代码为事实，立即修正文档并报告冲突

## 文档分级

| 级别 | 文件 | 用途 |
|------|------|------|
| L1 | `../AGENTS.md` | 模块入口，每次任务必读的硬约束 |
| L2 | 本目录下的专题文档 | 按任务类型按需加载 |
| L3 | 代码内注释 | 实现细节，随代码一起维护 |

## 写作约束

- **只描述当前代码实际行为**，不描述"应该怎样"或"计划怎样"
- 代码示例必须从实际源文件复制，不可手写假设性代码
- 变量名、函数名、文件路径必须与实际代码完全一致
- 发现代码与文档冲突时，以代码为准，修正文档
- 禁止在文档中放置敏感信息（路径、密钥、Token）
